# M3 收尾：详情页价格测算器 + 收藏页对比表

## Context（背景）

M3 里程碑剩余两项功能未完成（见「前端技术完善计划书」待办）：
1. **详情页价格测算器**：按用户输入的 token 用量估算调用费用
2. **收藏页多模型价格对比表**：横向对比收藏模型的定价

后端无需改动（价格单位：**元 / 百万 tokens**，数据字段两端 `types/model.ts` 完全一致）。需在 **client（uni-app Vue3）** 与 **taro-client（Taro React）** 两端同步实现，保持功能对齐。

## 设计要点

### 公共：各端新建 `utils/pricing.ts`（两端对称、内容一致）
- `formatPrice(v)`：单位价展示，`null` → `'免费'`，沿用现有 `¥${v}` 格式
- `calcCost(tokens, unit)`：`tokens/1e6 * unit`，`unit` 为 null 返回 null
- `formatCost(v)`：金额展示，`null` → `'免费'`；先 `Math.round(v*1e6)/1e6` 消浮点尾差，再 `Number(v.toFixed(4))` 去尾零（≥1 元至多 2 位，<1 元保留至多 4 位）
- 免费判定：`input==null && output==null` → 不计算，显示免费提示

### 功能 A：价格测算器（详情页）
- 位置：`detail.vue` / `detail.tsx` 「定价」卡片之后，新卡片「价格测算」
- 两个数字输入：输入 tokens / 输出 tokens
- 实时计算三组费用（输入 / 输出 / 合计）；模型有 `peak`/`offPeak`（如 DeepSeek）时额外展示「高峰时段」「空闲时段」两组
- **uni-app 写法**：`<input v-model="x" type="digit" />`，state 为 string，computed 中 `Number()` 解析、NaN 视为 0（不阻塞空串）
- **Taro 写法**：受控 `Input value={state} onInput={e => setState(e.detail.value)}`，state 存 string；H5 端正则 `^\d*\.?\d*$` 过滤非法字符

### 功能 B：多模型对比表（收藏页）
- 位置：`favorites/index.vue` / `index.tsx` 列表顶部，**仅 `list.length >= 2` 时展示**
- 表头：模型 | 输入 | 输出 | 缓存命中 | 上下文窗口；每行一个收藏模型，缓存无值显示 `-`
- 小程序无 table 标签：`view` + `flex` 网格，表头与数据行共用同一组列宽百分比类（模型 28%，其余各 18%）
- 模型名截断：名称列 `min-width:0; overflow:hidden; white-space:nowrap; text-overflow:ellipsis`

### 样式约定
- 两端 rpx 通用；Taro 多页 css 会合并为全局样式，新类名加 `pcalc-`（测算器）/ `cmp-`（对比表）前缀防碰撞
- uni-app 样式写在各页 SFC `<style>` 内，同样加前缀

## 验证

1. **client H5**：`cd client && npm run dev:h5`，详情页输入 token 量验证费用计算（含 DeepSeek 高峰/空闲两组、glm-4.5-flash 免费提示）；收藏 ≥2 个模型后收藏页出现对比表，缓存缺失显示 `-`
2. **client 小程序编译**：`npm run build:mp-weixin` 编译通过
3. **taro-client H5**：`cd taro-client && npm run dev:h5`，重复上述验证
4. **taro-client weapp 编译**：`npm run build:weapp` 编译通过
5. 免费模型与边界：空输入、0、超小 token 量（如 100 tokens → 金额接近 0 正常显示）
