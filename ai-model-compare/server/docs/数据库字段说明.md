# 数据库字段说明文档

> 对应代码：`server/src/dao/db.js`（建表）、`server/src/data/models.data.js`（演示数据）、`server/src/seed/seed.js`（数据初始化）
> 数据库文件：`server/data/models.db`（SQLite，执行 seed 或首次启动时自动创建）

## 1. 概览

| 表名 | 作用 | 主键 | 数据来源 |
|---|---|---|---|
| models | AI 模型定价信息 | id | seed 脚本写入 10 条演示数据 |
| favorites | 用户收藏记录 | (user_id, model_id) 联合主键 | 运行时由收藏接口写入 |

两表关系：**favorites.model_id → models.id（N:1）**
- 一条收藏记录对应一个模型
- 一个模型可被多条收藏记录引用

## 2. models —— 模型定价表

| 字段 | 类型 | 约束 | 说明 | 示例 |
|---|---|---|---|---|
| id | TEXT | PK | 模型唯一标识（主键） | `deepseek-chat` |
| model_name | TEXT | NOT NULL | 模型显示名 | `deepseek-chat` |
| vendor | TEXT | NOT NULL | 所属厂商 | `DeepSeek` |
| context_length | INTEGER | NOT NULL | 上下文长度（K tokens） | `128` |
| max_output | INTEGER | NOT NULL | 最大输出长度（K tokens） | `8` |
| price_list | TEXT | NOT NULL | 价格表，**JSON 字符串** | `{"input":0.8,"output":2}` |
| features | TEXT | NOT NULL | 特性标签，**JSON 数组字符串** | `["通用对话","推理"]` |
| purchase_url | TEXT | NOT NULL | 官方购买 / 控制台地址 | `https://platform.deepseek.com` |
| free | INTEGER | DEFAULT 0 | 是否免费（0/1） | `0` |
| remark | TEXT | 可空 | 备注说明 | `V3.2 系列，非思维链模型` |

> **为什么 price_list / features 用 JSON 字符串存？**
> 不同厂商的价格结构不统一（部分有缓存价 `cacheHit`、峰谷价 `peak/offPeak`），
> 存成 JSON 字符串可原样保留结构，读取时 `JSON.parse` 还原，由前端按"字段是否存在"做兼容展示。

## 3. favorites —— 用户收藏表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| user_id | TEXT | PK（联合） | 用户标识（本项目未做登录，由前端自定义传入） |
| model_id | TEXT | PK（联合）/ FK | 收藏的模型 id，逻辑关联 models.id |
| created_at | TEXT | NOT NULL | 收藏时间，默认取数据库本地时间 |

- 联合主键 `(user_id, model_id)` → 同一用户对同一模型最多一条收藏
- `INSERT OR IGNORE` 利用联合主键实现"重复收藏静默忽略"（天然幂等，无需先查重）

## 4. 关键设计点

| 设计点 | 位置 | 说明 |
|---|---|---|
| 字段命名 snake_case ↔ 对象 camelCase | `src/dao/model.dao.js` | 库里下划线命名，DAO 层 `rowToModel` 转换后供 JS 使用 |
| 布尔用 0/1 | models.free | SQLite 没有布尔类型 |
| 幂等写入 | `INSERT OR REPLACE` / `INSERT OR IGNORE` | seed 可重复执行、收藏不会重复 |
| 事务批量写入 | `modelDao.insertMany` | `db.transaction()` 包裹，全部成功或整体回滚 |
| 预编译 SQL | `db.prepare` | 复用编译结果性能更好，参数化传值防 SQL 注入 |

## 5. 数据流向

```
src/data/models.data.js (静态演示数据)
        │  npm run seed
        ▼
   models 表 (SQLite models.db)
        │  model.dao
        ▼
   model.service (关键字/厂商筛选、详情)
        │
        ▼
   GET /api/models → { code, message, data } JSON 响应给前端
```

收藏流程：前端传 userId → `POST / DELETE /api/favorites` → favorite.service 参数与业务校验（如"收藏的模型必须存在"）→ favorite.dao 写 favorites 表。

## 6. 常用 SQL 示例

```sql
-- 查询某用户收藏的模型 id（最新收藏在前）
SELECT model_id FROM favorites WHERE user_id = 'u1' ORDER BY created_at DESC;

-- 查询某厂商下所有免费模型
SELECT * FROM models WHERE vendor = '智谱GLM' AND free = 1;

-- 被收藏次数最多的前 3 个模型
SELECT model_id, COUNT(*) AS cnt FROM favorites GROUP BY model_id ORDER BY cnt DESC LIMIT 3;

-- 收藏明细（关联两表）
SELECT f.user_id, f.created_at, m.model_name, m.vendor
FROM favorites f JOIN models m ON f.model_id = m.id
WHERE f.user_id = 'u1';
```

## 7. 注意事项

- 演示项目为简化，`favorites.model_id` 未建立真正的数据库外键约束；若删除模型，收藏记录不会被级联删除
- 若后续删除模型，建议在接口层先清理相关收藏（当前 `favoriteService.remove` 幂等，可安全重复调用）
